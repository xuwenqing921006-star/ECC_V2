# 中央流程门禁独立验收与修复计划

> 框架归档计划（分享脱敏版）：保留中央门禁修复范围、历史验证记录和通用经验，移除无关业务项目的任务、分支、提交及机器路径。下文授权与验证记录仅描述当时的修复工作。

用户已授权当时的中央门禁独立验收。框架代码遵循修复—独立复验闭环，不能虚构既有开发许可，也不能把业务项目台账改作框架台账。

范围：workflow-guard、CLI、相关中央文档/模板与独立反例。先独立复现错误放行，再最小修复，独立 Tester 复验。开发者为主代理，Tester 为 guard_independent_review，Tester 不修改实现。

验收标准：失败/阻塞任务不能宣布完成；不完整合同、错误类型、缺开发证据、证据路径逃逸被拒绝；正确开发合同和独立完成报告通过；Doctor 可精确检查本项目 Worktree；旧 full_independent 行为回归通过。

能力边界：CLI 返回非零只约束调用它的执行链，不拦截 Codex 的 apply_patch/exec，不认证人工填写的身份标记，不证明材料创建早于业务修改。不得再把这些文档/CLI 检查描述成已安装的工具层或 CI 硬拦截。部署、Git 发布不在本轮授权范围。

当时的框架完成条件：中央测试和独立复验通过；框架 Doctor 一致；精确差异可供后续提交审核。未授权提交/推送时，工作树保留待提交，不能把未提交称已集成。

## 通用经验：并行任务编号冲突处理

分配任务编号前，应依据 `git worktree list --porcelain` 返回的明确工作树路径，核对各工作树的 `.sdd/tasks.json`。不能只看当前分支或硬编码下一号。发现冲突时，仅调整本次任务，保留审计记录并重新核验，不修改其他在途任务。当前 CLI 未提供跨工作树原子编号分配。
