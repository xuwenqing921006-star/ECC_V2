# SDD H5 页面产品设计专项

本 Skill 只处理 **H5 页面**：手机浏览器、微信内网页、PWA 窄屏 Web。已有项目继承其技术栈；新项目由阶段 C 根据团队能力、生态、性能和交付目标确认框架及组件库。

不处理：桌面 Web 后台、原生 App、React Native、Flutter、uni-app、小程序、游戏、3D/Canvas 重交互、强营销视觉页。

参考基线：

- Ant Design Mobile：组件体系、移动端业务体验、Ant 业务经验。
- W3C Mobile Web Best Practices：移动 Web 可用性、导航、输入、页面布局。
- Material Layout：一致、可预测、响应式的布局区域与阅读长度原则。

## 触发时机

在以下任一阶段，只要界面类型包含 H5，就必须加载本 Skill：

1. 阶段 R：需求澄清中确认有客户 H5、微信内网页、PWA 或手机浏览器入口。
2. 阶段 B1：生成 `.sdd/tmp/ui-design-spec.md` 前。
3. 阶段 B2：绘制 H5 原型前。
4. 开发前回看原型：Developer 需要确认生产页面是否继承 H5 已确认规则。

如果同一项目同时包含 H5 和桌面 Web 后台，必须拆分设计口径：H5 使用本 Skill；Web 后台继续使用桌面 Web / Ant Design 后台规则。

## H5 需求澄清补充

在通用产品问题之外，H5 页面还必须确认：

1. **入口环境**：手机浏览器、微信内 H5、PWA，还是三者都支持。
2. **首屏任务**：用户打开页面后第一件事是什么，首屏不能放与任务无关的大段说明。
3. **登录与身份**：免登录、账号密码、验证码、企业客户账号、Token 续期中的哪一种。
4. **主流程形态**：对话、表单、列表、详情、向导、结果页、支付/提交确认。
5. **底部操作**：是否需要固定底部输入栏、主按钮、TabBar，不能多个底部操作互相抢位置。
6. **返回路径**：返回上一页、回首页、关闭 H5、进入历史记录或重新发起会话。
7. **弱网与加载**：关键请求是否需要骨架屏、Toast、Retry、离线/超时提示。
8. **安全区**：是否面向刘海屏、微信 WebView、iOS 底部 home indicator，需要 SafeArea。

## H5 信息架构原则

- **单列优先**：手机 H5 默认单列，不把桌面表格、复杂筛选栏、左右分栏搬到手机。
- **首屏聚焦**：首屏只放当前用户最可能执行的任务；辅助说明收敛为小字、提示条或空状态。
- **一屏一主动作**：每个页面只保留一个最强主操作；次要动作降级为文本按钮、图标按钮或更多菜单。
- **底部慎用**：底部固定区域只用于持续输入、提交、确认、TabBar 等强流程控件。普通页面不要为了“像移动端”硬贴底。
- **状态可见**：加载、提交中、已完成、失败、转人工、只读等状态必须可见，但不要用解释性长文案塞满卡片。
- **H5 与 Web 后台分离**：H5 追求窄屏任务完成效率；Web 后台追求信息密度、批量处理和扫描效率。

## 推荐页面模式

| 页面类型 | 默认结构 | 常用组件 |
|----------|----------|----------|
| 登录页 | 顶部标题 + 表单面板 + 主按钮 | NavBar / Form / Input / Checkbox / Button |
| 对话页 | 顶部栏 + 消息流 + 快捷入口 + 底部输入栏 | NavBar / Avatar / Popup / Toast / SafeArea |
| 历史列表 | 顶部返回 + 卡片列表 + 状态标签 + 时间 | NavBar / Card / Tag / List / InfiniteScroll |
| 表单页 | 分组表单 + 底部提交 + 错误提示 | Form / Input / Picker / Selector / Button |
| 详情页 | 标题摘要 + 分组信息 + 相关操作 | Card / Collapse / Tag / Footer |
| 结果页 | 结果状态 + 核心信息 + 下一步动作 | Result / Button / Footer |
| 空/异常页 | 简短原因 + 恢复动作 | Empty / ErrorBlock / Button |

## 视觉与交互规则

- **视口**：默认按 390×844 设计和截图验证；必要时补 360×780 与 430×932。
- **头部**：标题居中；左侧放返回或新建等入口，右侧放历史、更多等辅助入口。图标按钮优先于文字按钮。
- **图标**：使用语义明确的 SVG/Icon。不要用单个汉字、emoji 或无语义图形充当头像、入口或状态。
- **卡片层级**：卡片、气泡、快捷入口、状态提示可用浅边框、细分隔线、轻微阴影形成层级，但避免过重投影。
- **输入控件**：输入框高度收敛，字号与正文一致；发送/提交按钮不得被挤成竖排；转人工、附件、语音等工具按钮要与输入框视觉区分。
- **列表卡片**：标题和状态放上方，摘要放中部，时间与时间图标放右下或次级位置；卡片之间必须有间距。
- **触控目标**：主要可点击区域尽量不小于 44px；紧凑图标也要有足够点击热区。
- **反馈**：轻反馈用 Toast；流程阻断用 Dialog/Modal；半屏选择用 Popup/Picker；不要把桌面 Modal 直接搬到手机。
- **安全区**：底部固定栏必须考虑 SafeArea，避免被系统手势区遮挡。

## B1 Design Spec 补充字段

当项目包含 H5 页面，`.sdd/tmp/ui-design-spec.md` 必须补充：

```markdown
## H5 页面设计规则
- H5 范围：手机浏览器 / 微信内 H5 / PWA
- 目标视口：390×844（必要时补充 360×780 / 430×932）
- 页面模式：登录 / 对话 / 历史列表 / 表单 / 详情 / 结果 / 空异常
- 顶部栏规则：标题位置、左侧入口、右侧入口
- 底部区域规则：是否固定、包含哪些操作、SafeArea 处理
- 组件库基底：Ant Design Mobile
- 图标规则：哪些入口必须使用 SVG/Icon，禁止文字代替图标
- 层级规则：卡片、气泡、状态提示、列表之间如何用边框/阴影/分隔线区分
- 不适用范围：不套用到桌面 Web 后台页面
```

## B2 原型验收清单

H5 原型提交用户确认前，必须检查：

- 是否以 390×844 视口截图验证。
- 页面是否无黑色手机外框等不必要装饰；除非用户明确要求展示设备壳。
- 头部、内容区、底部操作区是否层级明确。
- 底部固定栏是否贴底且没有遮挡内容。
- 输入框、按钮、图标是否适合手指点击。
- 所有按钮文字是否横向显示，未被窄宽度挤压。
- 聊天气泡、状态提示、快捷入口、历史卡片是否有足够层次。
- 历史列表、表单、详情页是否避免桌面表格化。
- 所有显示文字是否中文，且没有解释性冗余文案。
- 如果同项目有 Web 后台，H5 视觉规则是否没有误用到 Web 后台。

## Developer 交接要求

H5 原型完成后，必须把以下内容交给开发任务：

- 页面清单与路由。
- Ant Design Mobile 组件清单。
- 全局 H5 布局规则：视口、头部、底部、安全区、卡片层级。
- 关键状态：loading、error、empty、disabled、submitted、readonly。
- Mock 数据结构和真实 API 位置。
- 已被用户视觉确认的细节，不得在生产实现中丢失。
